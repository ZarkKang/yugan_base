### 链路 3: 心跳上报 — 🔴 严重问题

**端点**: `POST /api/drones/{drone_id}/shelves/sync`（无人机当前复用货架同步路径）
**基站实际心跳端点**: `POST /api/drones/heartbeat`（[drone_api.py:61](file:///e:/A0.software/The%20computer%20files/%E6%A1%8C%E9%9D%A2/%E5%9F%9F%E6%84%9F%E6%99%BA%E8%83%BD/yugan_base/station/warehouse-inspection-system/backend/src/api/drone_api.py#L61)）

#### 3.1 无人机发送格式

```json
{
  "drone_code": "DRONE001",
  "position": {"x": 0.0, "y": 0.0, "z": 0.0},
  "status": "running",
  "battery": 86.0,
  "timestamp": 1783260000.0
}
```

#### 3.2 严重问题

| # | 问题 | 严重程度 | 影响 |
|---|------|---------|------|
| 3.1 | **路径错误** — 无人机用心跳数据调用 `shelves/sync` 端点 | 🔴 致命 | 详见 3.3 |
| 3.2 | **货架归档副作用** — `shelves` 字段缺失，基站误认为"yaml无货架" | 🔴 致命 | 所有活跃货架被误归档 |
| 3.3 | 状态值不匹配 — 无人机 `running`/`completed` vs 基站 `idle`/`flying`/`online`/`offline`/`maintenance` | ⚠️ 中 | Drone.status 值不规范 |
| 3.4 | `timestamp`(unix) vs `last_heartbeat`(ISO8601) 格式不一致 | 低 | 基站用 `datetime.utcnow()` 替代 |
| 3.5 | `drone_code` 字段被忽略 | 低 | 基站用路径参数 `drone_id` |

#### 3.3 致命问题详解：路径错误导致货架归档

无人机当前配置 `heartbeat_path:=/api/drones/{drone_id}/shelves/sync`，将心跳数据发到了货架同步端点。执行流程：

1. 无人机发送心跳 `{drone_code, position, status, battery, timestamp}` → `POST /shelves/sync`
2. 基站 `DroneShelfSyncRequest` 解析：`shelves=[]`（默认空数组），`coordinate_frame=None`
3. `sync_shelves_from_drone()` 执行：
   - `active_shelves` = 数据库中所有未归档货架
   - `yaml_codes` = 空集（因为 `shelves=[]`）
   - **归档逻辑触发**：所有 `active_shelves` 中不在 `yaml_codes` 的货架 → `status="archived"` + `archived_at=now`
4. **结果**：每次心跳都会归档所有货架！

> 🔴 **此问题会导致数据库货架数据被破坏，必须优先修复**。

#### 3.4 修复方案

**方案 A（推荐）**：修改无人机端 `4.sh` 配置
```bash
heartbeat_path:=/api/drones/heartbeat
```
- 优点：基站端无需改动
- 缺点：需要 SSH 到无人机修改配置；心跳 body 中 `drone_id` 必须是整数（无人机需先调用 `/lookup` 获取）

**方案 B**：基站端在 `shelves/sync` 端点增加心跳数据检测
- 若 body 中无 `shelves` 字段但有 `battery`/`status`/`position`，则按心跳处理
- 优点：兼容无人机当前配置
- 缺点：违反单一职责原则

#### 4.3 严重问题

| # | 问题 | 严重程度 | 影响 |
|---|------|---------|------|
| 4.1 | **waypoint_id 语义冲突** — 无人机发送货柜编号 `01-01`，基站用 `Waypoint.id` 查询（格式 `wp_xxxxxxxx`） | 🔴 致命 | 查不到航点 → 返回 404 |
| 4.2 | `command: "WAYPOINT_ARRIVED"` 字段被忽略 | ⚠️ 中 | 信息丢失，但功能不受影响 |
| 4.3 | `waypoint_index` 字段被忽略 | ⚠️ 中 | 丢失航点顺序信息 |
| 4.4 | `position` 字段缺失 — 无人机未发送位置 | ⚠️ 中 | 位置校验失效，clip 截取无位置信息 |
| 4.5 | `timestamp`(unix) vs `arrived_at`(ISO8601) | ⚠️ 中 | 到达时间丢失 |
| 4.6 | `drone_code` 字段被忽略 | 低 | 基站用路径参数 |

#### 4.4 致命问题详解：waypoint_id 语义冲突

无人机端文档明确说：
> `waypoint_id` 对应货柜编号

但基站端实现：
```python
waypoint = db.query(Waypoint).filter(Waypoint.id == waypoint_id).first()
```

- `Waypoint.id` 是数据库主键，格式 `wp_xxxxxxxx`（自动生成）
- 无人机发送的 `waypoint_id` 是货柜编号 `01-01`
- **结果**：`Waypoint.id == "01-01"` 查不到记录 → 返回 404

#### 4.5 修复方案

**修复 1**：基站端改为按 `shelf_code` 查询航点
```python
# 优先按 id 查询，若未找到再按 shelf_code 查询
waypoint = db.query(Waypoint).filter(Waypoint.id == waypoint_id).first()
if not waypoint:
    # 无人机端 waypoint_id 实为货柜编号
    waypoint = db.query(Waypoint).filter(
        Waypoint.shelf_code == waypoint_id,
        Waypoint.task_id == payload.task_code,
    ).first()
```

**修复 2**：扩展 `WaypointArriveRequest` Schema 兼容无人机字段
```python
class WaypointArriveRequest(BaseModel):
    task_code: Optional[str] = None
    position: Optional[Dict[str, float]] = None
    arrived_at: Optional[datetime] = None
    # 新增兼容字段
    drone_code: Optional[str] = None
    command: Optional[str] = None
    waypoint_index: Optional[int] = None
    timestamp: Optional[float] = None  # unix 时间戳
```

**修复 3**：`timestamp` → `arrived_at` 自动转换
```python
if payload.timestamp and not payload.arrived_at:
    payload.arrived_at = datetime.fromtimestamp(payload.timestamp)
```

## 三、跨链路通用问题

### 3.1 时间戳格式不一致

| 来源 | 格式 | 示例 |
|------|------|------|
| 无人机端 | Unix 时间戳（float，秒） | `1783260000.0` |
| 基站端 | ISO8601 datetime | `2026-07-06T10:30:00` |

**影响链路**：1（货架同步）、3（心跳）、4（航点到达）、5（RFID）

**修复建议**：基站端 Schema 增加 `timestamp: Optional[float]` 字段，在端点内部转换为 `datetime`。

### 3.2 drone_code 与 drone_id 混用

| 场景 | 无人机发送 | 基站期望 |
|------|-----------|---------|
| 路径参数 | `drone_id`（已通过 lookup 获取） | `drone_id: int` ✅ |
| Body 字段 | `drone_code: "DRONE001"` | **未接收** |

**影响**：低 — 基站用路径参数 `drone_id` 查询无人机，body 中的 `drone_code` 冗余。

**建议**：Schema 增加 `drone_code: Optional[str]` 用于日志和交叉验证。

### 3.3 状态值枚举不一致

| 无人机状态 | 基站 Drone.status 枚举 |
|-----------|----------------------|
| `running` | `idle` / `flying` / `online` / `offline` / `maintenance` |
| `completed` | （无对应值，应为 `idle`） |

**修复建议**：基站端增加状态映射逻辑：
```python
STATUS_MAP = {
    "running": "flying",
    "completed": "idle",
}
drone.status = STATUS_MAP.get(payload.status, payload.status)
```
