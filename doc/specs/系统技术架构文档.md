## 第一章：系统架构模块

### 1.1 模块功能概述

系统架构模块定义了整个域感智能系统的网络拓扑结构、数据流转路径以及各子系统间的协作关系。本系统采用**基站-无人机协同架构**，通过局域网实现实时数据传输与任务调度。

#### 核心子系统组成

| 子系统 | IP地址 | 端口 | 技术栈 | 主要职责 |
|--------|--------|------|--------|----------|
| **基站端** (Edge Server) | 192.168.1.200 | 8080 | FastAPI + PostgreSQL + Redis + Docker | 任务调度、数据接收、异常判定、报告生成、图传中继 |
| **无人机端** (Jetson NX) | 192.168.1.201 | - | Ubuntu 22.04 + ROS2 Humble | 航点巡航、图像采集、QR码识别、RFID复核、实时图传 |
| **桌面应用** (Electron) | 192.168.1.x | - | Electron 28 | 任务管理、实时监控、报告查看/导出 |

---

### 1.2 核心设计思路

#### 1.2.1 分布式协同设计原则

```
基站端 (192.168.1.200)
├── 统一调度中心：任务创建、分配、监控
├── 数据处理枢纽：扫码结果汇总、异常判定、报告生成
├── 图传中继节点：接收无人机视频流 → 转发给前端
└── 持久化存储：PostgreSQL 数据库 + Redis 缓存

无人机端 (192.168.1.201)
├── 自主巡航执行器：按航点序列飞行、避障控制
├── 多传感器采集：摄像头、激光雷达、RFID读取器
├── 本地智能处理：QR码识别（多尺度多策略）、质量评估
└── 实时数据上报：HTTP REST API + WebSocket 图传
```

**设计决策**：
- **职责分离**：基站负责"决策与判定"，无人机负责"执行与采集"
- **轻量机载**：无人机仅处理图像采集和基础识别，复杂判定逻辑在基站执行
- **实时通信**：WebSocket 用于图传（低延迟），HTTP REST 用于数据上报（可靠性强）
- **混合架构**：基站采用 Docker 微服务化，无人机采用 ROS2 分布式节点

#### 1.2.2 局域网隔离设计

系统部署在独立局域网 `192.168.1.0/24`，确保：
- **网络隔离**：与外网物理隔离，避免外部攻击
- **低延迟传输**：千兆以太网或 5G WiFi，图传延迟控制在 200ms 内
- **固定IP分配**：基站与无人机固定IP，简化配置管理

#### 2.2.2 QR码识别增强策略

核心变更：**二维码识别由基站集中处理，无人机仅负责图像采集和上传**

```python
# EnhancedQRDecoder 核心策略
class EnhancedQRDecoder:
    scales = [0.5, 0.75, 1.0, 1.25, 1.5, 2.0]  # 多尺度解码
    preprocess_strategies = [
        'original',
        'gaussian_blur',
        'bilateral_filter',
        'histogram_eq',
        'adaptive_threshold',
        'sharpen'
    ]
    
    def decode(self, image):
        """
        遍历所有尺度 + 预处理策略组合
        返回: (qr_data, confidence)
        """
        # 1. 图像质量评估（拉普拉斯方差）
        quality = self.estimate_quality(image)
        
        # 2. 多尺度多策略解码
        for scale in self.scales:
            resized = cv2.resize(image, scale)
            for strategy in self.preprocess_strategies:
                processed = self._preprocess(resized, strategy)
                result = self._single_decode(processed)
                if result and result[1] >= self.min_confidence:
                    return result
        
        # 3. 失败触发 RFID 复核（可选）
        if not result:
            return None
```

```python
        """
        核心接口：上传扫码数据
        scan_data 结构:
        {
            "drone_id": "DRONE001",
            "task_id": "T001",
            "waypoint_id": "W015",
            "scan_type": "qr",
            "qr_data": "SKU123456",
            "confidence": 0.95,
            "image_quality": 85.0,
            "image_url": "http://192.168.1.200:8080/images/001.jpg",
            "position": {"x": 1.5, "y": 2.0, "z": 3.0},
            "timestamp": "2024-01-01T10:30:15Z"
        }
        
        返回:
        {
            "success": true,
            "verification": {
                "status": "normal",  # normal/misplaced/missing/extra/duplicate
                "expected_sku": "SKU123456",
                "message": "扫码成功，位置正确"
            }
        }
        """
        url = f"{self.base_url}/api/scan/upload"
        response = self._request("POST", url, json=scan_data)
        return response.json() if response else None
    
    def send_heartbeat(self, status_data: dict) -> bool:
        """心跳上报（每5秒）"""
        url = f"{self.base_url}/api/drones/heartbeat"
        response = self._request("POST", url, json=status_data)
        return response is not None and response.status_code == 200
```

```python
            # 1. 发送元信息（JSON）

            message = self.ws.recv()
```

```python
                    camera, qr_decoder, base_client, waypoint
                )
                
                # c. 上报进度

            # d. 完成任务
            base_client.complete_task(task_id, summary)
```

## 第三章：基站端模块

### 3.1 模块功能概述

基站端模块是系统的**中枢处理中心**，运行在 Edge Server (192.168.1.200) 上，采用 Docker Compose 微服务架构，负责：

- **任务调度与管理**：创建巡检任务、分配给无人机、监控执行进度
- **数据接收与处理**：接收扫码数据、图像、RFID数据，并进行异常判定

```python
# services/verification_engine.py
class VerificationEngine:
    """
    异常判定核心逻辑：
    1. 接收扫码数据 (qr_data + waypoint_id)
    2. 查询航点预期SKU (expected_skus)
    3. 比对判定异常类型
    """
    
    def verify(self, scan_data: dict) -> dict:
        waypoint = self.get_waypoint(scan_data['waypoint_id'])
        expected_skus = waypoint['expected_skus']
        actual_sku = scan_data['qr_data']
        
        # 1. 正常：扫码SKU匹配预期SKU
        if actual_sku in expected_skus:
            return {
                "status": "normal",
                "message": "扫码成功，位置正确"
            }
        
        # 2. 错位：扫码SKU不在预期位置
        else:
            correct_location = self.find_sku_location(actual_sku)
            return {
                "status": "misplaced",
                "expected_sku": expected_skus[0],
                "actual_sku": actual_sku,
                "correct_location": correct_location,
                "message": f"商品错位，应在位置 {correct_location}"
            }
        
        # 3. 缺货：预期SKU未扫到（置信度过低）
        if scan_data['confidence'] < 0.7:
            return {
                "status": "missing",
                "expected_sku": expected_skus[0],
                "message": "货架可能缺货"
            }
        
        # 4. 多货：同一航点扫描到多个SKU
        # 5. 重复：同一SKU在同一任务重复扫描
        # ...（后续扩展）
```

```python
# app/routers/report_router.py
@router.post("/api/reports/{task_id}/generate")
async def generate_report(task_id: str, db: Session = Depends(get_db)):
    """
    生成盘点报告（任务完成后自动或手动触发）
    
    1. 查询该任务所有扫码记录
    2. 统计分析（正常/错位/缺货/多货/重复）
    3. 生成异常清单（附带证据图）
    4. 保存报告记录
    """
    # 1. 查询扫码记录
    scans = db.query(ScanRecord).filter(ScanRecord.task_id == task_id).all()
    
    # 2. 统计分析
    normal_count = len([s for s in scans if s.verification_status == 'normal'])
    abnormal_count = len(scans) - normal_count
    
    # 3. 异常详情
    abnormal_items = []
    for scan in scans:
        if scan.verification_status != 'normal':
            abnormal_items.append({
                "waypoint_id": scan.waypoint_id,
                "status": scan.verification_status,
                "expected_sku": scan.expected_sku,
                "actual_sku": scan.qr_data,
                "image_url": scan.image_url,
                "message": scan.message
            })
    
    # 4. 生成报告
    report = InventoryReport(
        id=generate_uuid(),
        task_id=task_id,
        total_items=len(scans),
        scanned_items=len(scans),
        normal_items=normal_count,
        abnormal_items=abnormal_count,
        accuracy=normal_count / len(scans) * 100,
        details=abnormal_items,
        generated_at=datetime.utcnow()
    )
    
    db.add(report)
    db.commit()
    
    return APIResponse(
        success=True,
        message="报告生成成功",
        data={"report_id": report.id}
    )
```

### 5.1 模块功能概述

通信与接口模块定义了系统的**数据传输协议与接口契约**，包括：

- **HTTP REST API**：无人机与基站间的任务请求、数据上报、状态查询
- **WebSocket 实时通信**：无人机图传流、前端监控数据推送
- **接口数据格式规范**：请求/响应结构、错误码定义、字段约束

---

### 5.2 核心设计思路

#### 5.2.1 双通道通信架构

```
HTTP REST API (可靠数据上报)
├── 无人机 → 基站：任务请求、扫码数据、心跳
├── 特点：强一致性、失败重试、数据完整
└── 适用场景：关键业务数据传输

WebSocket (实时图传与监控)
├── 无人机 → 基站：实时视频流（JPEG帧）
├── 基站 → 前端：图传转发、状态推送、告警通知
├── 特点：低延迟、持续连接、双向通信
└── 适用场景：实时数据流、即时通知
```

#### 5.2.2 统一接口格式规范

**请求格式**（遵循项目编码铁律）：

```json
{
  "drone_id": "DRONE001",
  "task_id": "T001",
  "waypoint_id": "W015",
  "scan_type": "qr",
  "qr_data": "SKU123456",
  "confidence": 0.95,
  "position": {"x": 1.5, "y": 2.0, "z": 3.0},
  "timestamp": "2024-01-01T10:30:15Z"
}
```

**统一响应格式**（必须返回 `APIResponse`）：

```json
{
  "success": true,
  "message": "扫码数据接收成功",
  "data": {
    "verification": {
      "status": "normal",
      "expected_sku": "SKU123456",
      "message": "扫码成功，位置正确"
    }
  },
  "errors": null
}
```

**错误响应格式**：

```json
{
  "success": false,
  "message": "无人机不存在",
  "data": null,
  "errors": [
    {
      "code": "DRONE_NOT_FOUND",
      "detail": "drone_id: DRONE999 未在数据库中找到"
    }
  ]
}
```

### 5.3 关键实现要点

#### 5.3.1 HTTP REST API 接口清单

| 接口类型 | 端点 | 请求方法 | 请求体 | 响应体 | 说明 |
|----------|------|----------|--------|--------|------|
| **无人机管理** |
| 心跳上报 | `/api/drones/heartbeat` | POST | heartbeat dict | success bool | 每5秒调用 |
| 无人机列表 | `/api/drones` | GET | - | drones list | 查询所有无人机 |
| 无人机详情 | `/api/drones/{drone_id}` | GET | - | drone dict | 查询单个无人机 |
| **任务管理** |
| 可用任务 | `/api/drones/{drone_id}/tasks/available` | GET | - | tasks list | 无人机获取任务 |
| 接收任务 | `/api/drones/{drone_id}/tasks/{task_id}/accept` | POST | - | success bool | 确认任务 |
| 进度更新 | `/api/drones/{drone_id}/tasks/{task_id}/progress` | POST | progress dict | success bool | 上报进度 |
| 任务完成 | `/api/drones/{drone_id}/tasks/{task_id}/complete` | POST | summary dict | success bool | 任务完成 |
| **航点管理** |
| 航点列表 | `/api/tasks/{task_id}/waypoints` | GET | - | waypoints list | 获取航点序列 |
| 航点状态 | `/api/waypoints/{waypoint_id}/status` | PUT | status dict | success bool | 更新航点状态 |
| **扫码数据** |
| 单次上传 | `/api/scan/upload` | POST | scan_data dict | verification dict | 核心接口 |
| 批量上传 | `/api/scan/batch` | POST | scans list | success bool | 网络不稳定时使用 |
| 任务扫码 | `/api/scan/task/{task_id}` | GET | - | scans list | 查询任务扫码记录 |
| **报告管理** |
| 生成报告 | `/api/reports/{task_id}/generate` | POST | - | report_id | 任务完成后触发 |
| 报告详情 | `/api/reports/{report_id}` | GET | - | report dict | 查询报告 |
| 导出报告 | `/api/reports/{report_id}/export?format=json` | GET | - | report file | 导出JSON/Excel/PDF |

#### 5.3.2 WebSocket 实时通信协议

**无人机图传 WebSocket** (`/ws/video/{drone_id}`)：

```python
# 无人机发送帧信息（JSON）
{
  "frame_id": 12345,
  "timestamp": "2024-01-01T10:30:15.123Z",
  "size": 102400,  # bytes
  "format": "jpeg"
}

# 无人机发送二进制数据
[JPEG binary data]  # 约100KB，压缩率70%

# 基站可能下发控制指令
{
  "command": "pause"  # 或 "continue"
}
```

**前端监控 WebSocket** (`/ws/monitor`)：

```python
# 前端订阅指令
{
  "subscribe": "drone_001"  # 订阅指定无人机图传
}

# 前端取消订阅
{
  "unsubscribe": "drone_001"

{
  "type": "video_frame",  # 图传帧
  "drone_id": "DRONE001",

  "type": "scan_result",  # 扫码结果

  "verification_status": "normal"

  "type": "alert",  # 异常告警
  "message": "商品错位",
  "level": "warning"
}
```

#### 5.3.3 异常处理与错误码

**统一异常捕获**（全局 `exception_handler`）：

```python
# src/core/exceptions.py
class BusinessException(Exception):
    def __init__(self, message: str, code: str = "BUSINESS_ERROR"):
        self.message = message
        self.code = code

# 全局异常处理器
@app.exception_handler(BusinessException)
async def business_exception_handler(request, exc):
    return JSONResponse(
        status_code=400,
        content={
            "success": False,
            "message": exc.message,
            "data": None,
            "errors": [{"code": exc.code, "detail": exc.message}]
        }
    )
```

**标准错误码定义**：

| 错误码 | 说明 | HTTP状态码 |
|--------|------|-----------|
| `DRONE_NOT_FOUND` | 无人机不存在 | 404 |
| `TASK_NOT_FOUND` | 任务不存在 | 404 |
| `WAYPOINT_NOT_FOUND` | 航点不存在 | 404 |
| `INVALID_SCAN_DATA` | 扫码数据格式错误 | 400 |
| `NETWORK_ERROR` | 网络通信失败 | 500 |
| `DATABASE_ERROR` | 数据库操作失败 | 500 |

#### 6.2.2 Docker Compose 容器编排架构

```yaml
# docker-compose.yml
version: '3.8'

services:
  postgres:
    image: postgres:14
    container_name: yugan_postgres
    environment:
      POSTGRES_DB: yugan_db
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: admin123
    ports:
      - "5432:5432"  # 仅内部访问
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - yugan_network

  redis:
    image: redis:7
    container_name: yugan_redis
    ports:
      - "6379:6379"  # 仅内部访问
    networks:
      - yugan_network

  drone_db:
    build: ./drone-db-prototype
    container_name: yugan_drone_db
    ports:
      - "8000:8000"  # 仅内部访问
    depends_on:
      - postgres
      - redis
    environment:
      DATABASE_URL: postgresql://admin:admin123@postgres:5432/yugan_db
    networks:
      - yugan_network

  warehouse:
    build: ./warehouse-inspection-system
    container_name: yugan_warehouse
    ports:
      - "8001:8001"  # 仅内部访问
    depends_on:
      - postgres
      - redis
    environment:
      DATABASE_URL: postgresql://admin:admin123@postgres:5432/yugan_db
    networks:
      - yugan_network

  api_gateway:
    build: ./api-gateway
    container_name: yugan_gateway
    ports:
      - "0.0.0.0:8080:8080"  # 监听所有网络接口（重要！）
    depends_on:
      - drone_db
      - warehouse
    networks:
      - yugan_network

networks:
  yugan_network:
    driver: bridge

volumes:
  postgres_data:
```

**关键配置要点**：
- **API网关必须监听 `0.0.0.0:8080`**（不是 `127.0.0.1`），否则无人机无法连接
- **内部服务端口不对外暴露**（8000、8001 仅内部转发）
- **数据库持久化存储**（postgres_data volume）

### C. 常见问题排查指南

#### C.1 无人机无法连接基站

```bash
# 在无人机上执行
ping 192.168.1.200  # 检查网络连通性
curl http://192.168.1.200:8080/health  # 检查API

# 可能原因与解决方法：
# 1. 基站服务未启动 → 启动 Docker Compose
# 2. 防火墙阻止8080端口 → sudo ufw allow 8080
# 3. Docker容器端口映射错误 → 检查 docker-compose.yml
# 4. API网关监听127.0.0.1 → 修改为 0.0.0.0:8080
```

#### C.2 图传延迟高

```bash
# 排查步骤：
# 1. 检查网络带宽（建议千兆以太网或5G WiFi）
# 2. 降低图像分辨率（1280x720）
# 3. 提高JPEG压缩率（降低质量到50%）
# 4. 减少帧率（15fps）
```

#### C.3 扫码识别率低

```bash
# 排查步骤：
# 1. 检查摄像头对焦
# 2. 调整光照（避免强反光/过暗）
# 3. 启用多策略解码（已在方案中提供）
# 4. 降低飞行速度，增加扫码停留时间
# 5. 调整 min_confidence 阈值
```
