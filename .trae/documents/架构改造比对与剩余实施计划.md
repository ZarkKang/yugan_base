## 二、关键设计决策（已固化，不可回退）

基于上一轮对话用户明确澄清，以下决策为最终方向：

1. **视频不按航点切分**：单条 `VideoData` 记录对应一次完整 WS 流会话；到达航点时仅在 `waypoint_markers` JSON 数组中追加一条 `{waypoint_id, frame_index, timestamp, expected_sku, position}` 标记，**不创建新的 VideoData 行**
2. **QR 双图保存**：裁剪 QR 区域小图 + 带框选标注的原图，路径分别写入 `ImageRecord.qr_cropped_path` / `ImageRecord.annotated_path`
3. **WS 双模消息**：binary 帧承载 JPEG 图像数据；text 帧承载 JSON 控制消息（waypoint_enter / waypoint_leave / stream_start / stream_stop / heartbeat）
4. **api-gateway WS 代理必须用 `receive()` 而非 `receive_text()`**：现有 `/ws/monitor` 用 `receive_text()` 不支持 binary 上行，新 `/ws/video/{drone_code}` 代理必须用 `receive()` 按消息类型分发
5. **Electron 完全删除**：删除 `app/desktop-app/` 整个目录 + 改 3 个脚本 + 改 1 个文档，不留向后兼容

### Stage 4：WS 视频流端点 + 聚合器（约 2 天）

**目标**：实现 `/ws/video/{drone_code}` 端点，接收无人机 JPEG 帧流，聚合为视频文件，结束时触发 `postprocess_video`。

#### 4.1 新建 `station/warehouse-inspection-system/backend/src/services/video_stream_aggregator.py`

**核心类**：`VideoStreamAggregator`（单例）+ `DroneStreamSession`（每无人机会话）

**`DroneStreamSession` 字段**：
- `drone_code: str`
- `task_code: Optional[str]`
- `frame_buffer: list[bytes]`（待写入的 JPEG 帧缓冲）
- `frame_count: int`
- `start_time: datetime`
- `output_path: str`（聚合视频文件路径）
- `writer_thread: threading.Thread`（守护线程，从 frame_buffer 取帧写文件）
- `waypoint_markers: list[dict]`（航点标记数组）
- `lock: threading.Lock`
- `closed: bool`

**`VideoStreamAggregator` 方法**：
- `start_session(drone_code, task_code) -> DroneStreamSession`：创建会话，分配输出路径 `storage/videos/{task_code}/{drone_code}/ws_{session_id}.mp4`
- `push_frame(session, jpeg_bytes)`：追加到 frame_buffer，唤醒 writer_thread
- `mark_waypoint(session, waypoint_id, expected_sku, position)`：记录当前 frame_index + timestamp 到 waypoint_markers
- `close_session(session) -> (file_path, video_rec_id)`：等待 writer_thread 写完 → 创建 VideoData 记录（source="ws_stream", stream_session_id=session_id, waypoint_markers=JSON）→ 触发 `postprocess_video(source="ws_stream")`
- `shutdown_all()`：FastAPI shutdown 时调用，强制 flush 所有未关闭会话

**writer_thread 行为**：
- 用 `cv2.VideoWriter` 按预设 FPS（默认 15）写入 JPEG 帧
- 帧率不足时复制最后一帧补齐
- 异常时记日志，不抛出（守护线程）

#### 4.2 新建 `station/warehouse-inspection-system/backend/src/api/ws_video.py`

**端点**：`@router.websocket("/ws/video/{drone_code}")`

**处理流程**：
1. 接受 WS 连接，校验 `drone_code` 存在性（查 Drone 表）
2. 可选 query 参数：`task_code`、`session_id`
3. 启动 DroneStreamSession
4. 主循环 `while True: msg = await websocket.receive()`：
   - `msg["type"] == "websocket.receive"` + `bytes` → `aggregator.push_frame(session, msg["bytes"])`
   - `msg["type"] == "websocket.receive"` + `text` → 解析 JSON 控制消息：
     - `{"type": "stream_start", "task_code": "...", "drone_code": "..."}` → 关联 task
     - `{"type": "waypoint_enter", "waypoint_id": "W015", "expected_sku": "SKU123", "position": {...}}` → `aggregator.mark_waypoint(...)`
     - `{"type": "waypoint_leave", "waypoint_id": "W015"}` → 记录离开时间（可选）
     - `{"type": "stream_stop"}` → break 主循环
     - `{"type": "heartbeat"}` → 回 `{"type": "heartbeat_ack"}`
   - `msg["type"] == "websocket.disconnect"` → break
5. finally 块：`aggregator.close_session(session)` → 返回 file_path + video_rec_id

- Line 19 导入新增：`from .api import ..., ws_video, ...`

## 五、风险与兼容性

1. **WS 流帧率不足**：无人机网络抖动可能导致 VideoWriter 写入空帧。对策：writer_thread 检测空闲超 1s 时复制最后一帧补齐
2. **会话异常中断**：无人机断连时 DroneStreamSession 未正常关闭。对策：lifespan shutdown 强制 flush；同时设置会话超时（默认 5 分钟无帧即关闭）
3. **api-gateway binary 转发**：现有 `/ws/monitor` 不支持 binary，新代理必须独立实现，不能复用 forward 函数
4. **启动.bat 改动量大**：17 处引用，需逐处删除并重新编号菜单项，建议改完后人工跑一遍菜单确认
5. **`postprocess_video` 内部 broadcast**：当前实现调用 `_broadcast("video_processed", ...)`；WS 路径下事件名应保持一致，前端可统一订阅
6. **数据库迁移幂等性**：`migrations.py` 已用 `ADD COLUMN IF NOT EXISTS`，重复执行安全；但 `waypoint_markers` 字段为 TEXT，PostgreSQL 不校验 JSON 结构，应用层需自行校验

## 七、假设与前提

1. **用户最终澄清已固化**：视频不切分、仅标记帧位置（`waypoint_markers` JSON 数组）。本计划不再回退到 `segment_index` 方案
2. **`postprocess_video` 函数已正确实现**：Stage 3 仅需调用接入，不修改其内部逻辑
3. **api-gateway 与 warehouse 服务在同一 Docker 网络**：WS 代理上游 URL 用 `ws://warehouse:8001/...`（容器名解析）
4. **无人机端 WS 客户端会按规范发送双模消息**：binary 推帧 + text 控制消息。无人机端实现归入后续无人机端开发任务
5. **PostgreSQL 支持 `TEXT` 类型存储 JSON**：应用层负责序列化/反序列化，无需 PostgreSQL JSONB 扩展
