# 无人机端兼容性修复方案

## Context

根据 `doc/2026-07-06_REAL_DRONE_400_changes.md`，无人机端已将通讯重构为 5 条独立链路，但基站端 API 存在 3 个 P0 致命兼容性问题和 4 个 P1 重要问题，导致联调无法通过。本方案修复所有基站端问题，确保无人机无需修改即可正常通信。

---

## 问题总览

| 优先级 | 问题 | 链路 |
|--------|------|------|
| P0-1 | 心跳路径错误 → 货架被误归档 | 心跳 |
| P0-2 | waypoint_id 语义冲突（货柜编号 vs DB主键） | 航点到达 |
| P0-3 | RFID 上传端点缺失 | RFID |
| P1-1 | Schema 缺少无人机端字段（command/waypoint_index/timestamp 等） | 航点/心跳/货架 |
| P1-2 | 时间戳格式不一致（unix vs ISO8601） | 全部 |
| P1-3 | 状态值枚举不一致（running/completed vs flying/idle） | 心跳 |
| P1-4 | 航点到达缺 position → clip 位置校验失效 | 航点到达 |

## 步骤 2：修复 shelves/sync — 心跳数据检测

**核心问题**：无人机把心跳数据发到 `shelves/sync`，空 `shelves=[]` 导致所有货架被归档。

**修复策略**：在 `sync_shelves_from_drone()` 入口增加心跳数据检测。如果 body 中包含 `battery`/`status`/`position` 心跳字段且 `shelves` 为空，则自动路由到心跳处理逻辑。

```python
@router.post("/{drone_id}/shelves/sync")
def sync_shelves_from_drone(drone_id: int, payload: DroneShelfSyncRequest, ...):
    # ★ 心跳数据检测：若 body 含心跳字段且 shelves 为空，走心跳逻辑
    if _is_heartbeat_payload(payload):
        return _handle_misrouted_heartbeat(drone_id, payload, db)

    # 原有货架同步逻辑不变 ...
```

辅助函数：

```python
def _is_heartbeat_payload(payload: DroneShelfSyncRequest) -> bool:
    """检测是否为误路由到 shelves/sync 的心跳数据"""
    # shelves 为空 + 存在心跳特征字段（timestamp 但无 shelves 内容）
    # 无人机心跳: {drone_code, position, status, battery, timestamp}
    has_heartbeat_signals = (
        payload.timestamp is not None
        and len(payload.shelves) == 0
    )
    return has_heartbeat_signals

def _handle_misrouted_heartbeat(drone_id: int, payload, db: Session):
    """处理误路由到 shelves/sync 的心跳数据"""
    drone = _drone_or_404(db, drone_id)
    # 更新状态（不更新货架）
    if payload.timestamp:
        drone.last_seen = datetime.fromtimestamp(payload.timestamp)
    else:
        drone.last_seen = datetime.utcnow()
    db.commit()
    return APIResponse(success=True, message="心跳已接收(兼容路径)", data={...})
```

> 设计要点：`_is_heartbeat_payload` 的判断依据是 `shelves 为空 + timestamp 存在`。这是因为正常货架同步一定有 shelves 数据，而心跳数据一定没有 shelves。timestamp 是无人机心跳的必带字段。

## 步骤 4：修复 waypoint_arrive — shelf_code 回退查询

**核心问题**：无人机发送 `waypoint_id="01-01"`（货柜编号），但基站用 `Waypoint.id`（格式 `wp_xxx`）查询。

```python
@router.post("/{drone_id}/waypoints/{waypoint_id}/commands/arrive")
def waypoint_arrive(drone_id, waypoint_id, payload, db=...):
    drone = _drone_or_404(db, drone_id)

    # ★ 双重查询：先按 id 查，再按 shelf_code + task_code 查
    waypoint = db.query(Waypoint).filter(Waypoint.id == waypoint_id).first()
    if not waypoint and payload.task_code:
        # 无人机端 waypoint_id 实为货柜编号
        waypoint = db.query(Waypoint).filter(
            Waypoint.shelf_code == waypoint_id,
            Waypoint.task_id == payload.task_code,
        ).first()
    if not waypoint:
        raise HTTPException(status_code=404, detail=f"航点不存在: id或shelf_code={waypoint_id}")

    # ★ timestamp → arrived_at 自动转换
    if payload.timestamp and not payload.arrived_at:
        waypoint.scanned_at = datetime.fromtimestamp(payload.timestamp)
    elif payload.arrived_at:
        waypoint.scanned_at = payload.arrived_at

    # ★ 若 payload 缺 position，从 Waypoint 表读取（用于 clip 位置校验）
    position = payload.position
    if not position and waypoint:
        position = {"x": waypoint.position_x, "y": waypoint.position_y, "z": waypoint.position_z}

    # 更新航点状态
    waypoint.status = "scanning"
    if payload.waypoint_index is not None:
        waypoint.sort_order = payload.waypoint_index
    db.commit()

    # WS 帧标记 + clip 截取（使用修正后的 position）
    # ...

    return APIResponse(success=True, message="航点到达已确认", data={
        "waypoint_id": waypoint.id,           # 返回 DB 主键
        "shelf_code": waypoint.shelf_code,     # 返回货柜编号
        "waypoint_status": waypoint.status,
        "expected_sku": waypoint.expected_sku,
        "scan_timeout": 30,
        "ws_frame_marked": ws_marked,
        "clip_scheduled": clip_result.get("scheduled", False),
        "clip_position_warning": clip_result.get("position_warning"),
        "clip_message": clip_result.get("message"),
    })
```

## 步骤 5：新增 RFID 上传端点

```python
@router.post("/{drone_id}/rfid/upload", response_model=APIResponse)
def upload_rfid_data(drone_id: int, payload: DroneRfidUploadRequest, db=...):
    """
    无人机 RFID 扫描结果上传

    最后一个航点完成时统一上传所有 RFID 数据。
    """
    drone = _drone_or_404(db, drone_id)

    # 推断 task_code：优先用 payload，否则从当前运行任务获取
    task_code = payload.task_code
    if not task_code:
        running_task = db.query(Task).filter(
            Task.drone_id == drone_id,
            Task.status == TaskStatus.RUNNING,
        ).first()
        if running_task:
            task_code = running_task.task_code

    detected_at = (
        datetime.fromtimestamp(payload.timestamp) if payload.timestamp
        else datetime.utcnow()
    )

    saved_count = 0
    for item in payload.payload:
        try:
            rec = RFIDData(
                rfid_tag=item.get("rfid_tag") or item.get("epc") or item.get("tag_id", ""),
                tag_type=item.get("tag_type"),
                signal_strength=item.get("signal_strength"),
                latitude=item.get("latitude"),
                longitude=item.get("longitude"),
                altitude=item.get("altitude"),
                drone_id=drone_id,
                task_code=task_code,
                detected_at=detected_at,
            )
            db.add(rec)
            saved_count += 1
        except Exception as e:
            logger.warning(f"RFID 记录写入失败: {e}")

    db.commit()
    logger.info(f"RFID 上传完成: drone={drone.drone_code} task={task_code} count={saved_count}")

    return APIResponse(success=True, message=f"RFID 数据已接收，共 {saved_count} 条", data={
        "drone_id": drone_id,
        "task_code": task_code,
        "saved_count": saved_count,
    })
```

> 设计要点：`payload.payload` 使用 `List[dict]` 灵活解析，因为无人机端 RFID 项结构未确认。支持多种常见字段名（`rfid_tag`/`epc`/`tag_id`）。
